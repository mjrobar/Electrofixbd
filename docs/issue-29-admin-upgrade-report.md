## Database review and activation blockers

Exact proposed SQL: [optional 007](../db/optional/007_admin_upgrade.sql), SHA-256 `4b51a8b7f53a177c13d13b0b9f4fa1286f585ab0edbdd248556356523679d80a` (LF). Adds `admin_owner`, `admin_account_tokens`, `admin_notification_state`, `admin_delivery_outbox`, their constraints/queue indexes, private-table RLS/browser revokes, and a booking created-time/cursor index. It performs no seed, UPDATE or DELETE of existing records.

Separate [runtime grant SQL](../db/security/003_admin_upgrade_runtime_grants.sql), SHA-256 `eb0160c364b2add66ccec60b2fda3696fa59c7ff1650f6ee8b20e976dd52bf3f` (LF), requires an existing restricted role that does not own these tables and is not inherited by browser roles. It does not assume a public migration ledger. Both SQL files are **prepared, not applied**. They are outside the automatic baseline migration directory and need explicit owner approval through the existing migration system. Do not replay 001–006 or run migration repair.

Activation order, private native/media backup, exact environment variables, safe rollback and operator commands are in the [operator runbook](issue-29-operator-runbook.md). Account changes, shared unread persistence and delivery queues remain disabled against existing databases until SQL/grants/bootstrap are explicitly approved and verified.
